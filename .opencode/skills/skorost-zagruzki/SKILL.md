# Технический аудит сайта (методология «Текарт»)

## Результаты пункта 4.1
1. **`Скорость_<хост>.xlsx`** — два листа: **«Десктоп»** и **«Мобильные»**, колонки:
   `url, Оценка, LCP, TBT, FCP, SI, TTI, CLS`.
2. **`Скорость загрузки страниц.docx`** — подводка (зачем скорость загрузки), средние оценки (десктоп/мобильные),
   проблемы и рекомендации **простым, понятным языком** (ориентир — Frontside), таблица худших страниц.

## Порядок работы

> **Отчёты о ходе (для прогресс-бара).** Выведи `[[stage:1/3]]` в начале, `[[stage:2/3]]` перед
> прогоном PageSpeed и `[[stage:3/3]]` перед сохранением файлов.

1. **Собрать все URL** — sitemap.xml + краулинг по перелинковке (как в пунктах 2.1–2.5).
2. **Прогнать каждую страницу через Google PageSpeed** и выписать метрики: оценка, LCP, TBT, FCP, SI, TTI, CLS
   (отдельно для десктопа и для мобильных).
   - Прямой API `pagespeed.web.dev`/`pagespeedonline` без ключа быстро упирается в дневную квоту,
     поэтому используется сервис **`https://coolakov.ru/tools/pagespeed/`** (батч, считает параллельно,
     у него свой ключ). Скрипт шлёт список URL одним/несколькими батчами и парсит обе таблицы.
   - Фолбэк — прямой PageSpeed Insights API (если доступен).
3. **Сформировать** XLSX и DOCX.

## Что писать в документе (простым языком)
- **Подводка** — почему скорость загрузки важна: пользователи уходят с медленных страниц, поисковики
  учитывают Core Web Vitals (особенно на мобильных), быстрый сайт даёт больше конверсий.
- **Средние оценки**: десктоп X из 100, мобильные Y из 100, и в какой зоне (хорошо/требует улучшения/плохо).
- **Проблемы** — понятные: мобильные страницы в оранжевой/красной зоне; долго появляется основной контент (LCP);
  «прыгает» вёрстка (CLS); причины — тяжёлые картинки, лишние скрипты и виджеты.
- **Рекомендации** — что сделать: сжать/перевести изображения (см. п. 2.4), задать размеры и lazy-load,
  отложить виджеты и счётчики, убрать лишний CSS/JS, включить сжатие и кэш, оптимизировать шрифты, проверить хостинг.
- **Сводная таблица** — файл `Скорость_<хост>.xlsx` (листы «Десктоп», «Мобильные»).

## Техника
Скрипт: `scripts/speed_audit.py`
```bash
python3 scripts/speed_audit.py --url https://<host>/ --out-dir <папка> [--limit 200] [--chunk 60]
```
Зависимости: `pip3 install --break-system-packages requests beautifulsoup4 openpyxl python-docx`.
Прогон по многим страницам занимает несколько минут (сервис считает параллельно, ~1 батч на 40–60 URL).

## Что НЕ относится к пункту 4.1
- Оптимизация изображений как таковая — пункт 2.4 (в 4.1 ссылаемся на неё).
- Перебои в работе сайта — пункт 4.2.
- Внешние показатели (сниппеты, ссылки) — 3.1/3.2.

## Глубина проверки (крупные сайты)
Проверяй **выборочно** — самые важные страницы (главная, «О компании», каталоги/разделы, разводящие страницы, контакты, карточки товаров/услуг и другие важные), чтобы сделать вывод о состоянии сайта. Скрипт ранжирует страницы по важности (`importance_rank`): сначала главная и контакты/«о компании», затем каталоги/разводящие, затем карточки/услуги, а новости/блог/статьи — в конце. В SEO-центре глубина задаётся полем «Пункт 4.1 «Скорость загрузки» — глубина» (по умолчанию 10) и передаётся в скрипт параметром `--limit N`. Если указано больше 1000 — проверяются все страницы (предупреди, что это займёт много времени).
