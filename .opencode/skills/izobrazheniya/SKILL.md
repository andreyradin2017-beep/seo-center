# Технический аудит сайта (методология «Текарт»)

## Результаты пункта 2.4

1. **`Изображения.docx`** — отчёт: подводка (зачем важны изображения), тезисно проблемы, тезисно
   рекомендации (для поисковых систем и для скорости загрузки), таблица примеров.
2. Листы в **общей таблице по контенту `Контент_<хост>.xlsx`** (открывать существующий, не создавать новый):
   - **«Изображения»** — `№, Файл (src), Alt, Title, Width (attr), Height (attr), Реальный размер, Формат, Вес КБ, Страниц, Lazy, Проблемы`;
   - **«Рекомендации по изображениям»** — что сделать по каждому изображению (alt, размеры, формат, целевой вес).

## Порядок работы

> **Отчёты о ходе (для прогресс-бара).** Выведи `[[stage:1/3]]` в начале, `[[stage:2/3]]` перед
> проверкой изображений и `[[stage:3/3]]` перед сохранением файлов.

1. **Собрать все URL** — как в пунктах 2.1–2.3 (sitemap.xml + краулинг по перелинковке).
2. **На каждой странице собрать все `<img>`** (локальные, без data: и внешних счётчиков): `src`, `alt`, `title`,
   атрибуты `width`/`height`, inline-стили размеров, `loading`, `srcset`.
3. **Проверить каждое изображение:**
   - **Вес** — размер файла (тяжёлое > 100 КБ, очень тяжёлое > 200 КБ).
   - **Сжатие** — вес относительно размеров.
   - **Формат** — JPG/PNG/GIF/BMP вместо WebP/AVIF.
   - **Разрешение** — реальный размер vs отображаемый: избыточное (реально ≥ 2× отображения, например
     5000px в блок 200px) или недостаточное (реально меньше отображения — растянуто/размыто);
     слишком крупные по ширине (> 2000px).
   - **Alt** — отсутствует/пустой/слишком длинный; **title** — при отсутствии отметить как замечание.
   - **width/height** — отсутствуют (риск CLS); **loading=lazy** — отсутствует.
4. **Сформировать** `.docx` и листы XLSX.

## Структура .docx
- Обложка (название 24pt #333333, дата 9pt #942972, таблица проекта).
- `Heading 1` — «Анализ страничных факторов», `Heading 2` — «2.4. Изображения».
- **Подводка** — почему изображения важны: релевантность и поиск по картинкам, UX, скорость и Core Web Vitals (LCP, CLS).
- **«В ходе проверки выявлены следующие проблемы:»** — тезисно (вес, формат, разрешение, alt/title, размеры, lazy).
- **«Рекомендация:»** — отдельно **для поисковых систем** (alt, title, имена файлов, релевантность)
  и **для скорости загрузки** (формат WebP/AVIF, сжатие, соответствие размеров, width/height, lazy/fetchpriority).
- Таблица примеров изображений, требующих доработки.

## Техника

Готовый скрипт: `scripts/image_audit.py`. Запуск:

```bash
python3 scripts/image_audit.py --url https://<host>/ --out-dir <папка результатов>
```

Скрипт сам: собирает URL, извлекает изображения, скачивает их (кеширует), определяет вес, формат и
реальные размеры (Pillow), сравнивает с отображаемыми, находит проблемы, пишет листы «Изображения» и
«Рекомендации по изображениям» в `Контент_<хост>.xlsx` и сохраняет `Изображения.docx`.
Зависимости: `pip3 install --break-system-packages requests beautifulsoup4 openpyxl python-docx pillow`.

## Что НЕ относится к пункту 2.4
- Текст — 2.1; заголовки H1–H6 — 2.2; теги title/description — 2.3.
- Исходящие ссылки — 2.5; микроразметка — 2.6.
- Адресация/дубликаты/индексация/перелинковка — 1.1–1.5.
