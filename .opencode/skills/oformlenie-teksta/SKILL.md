# Технический аудит сайта (методология «Текарт»)

## Результаты пункта 2.2

1. **`Оформление текста.docx`** — отчёт: подводка (зачем нужна структура текста и заголовки),
   тезисно проблемы, тезисно рекомендации, таблица примеров по страницам.
2. Листы в **общей таблице по контенту `Контент_<хост>.xlsx`** (не создавать новый workbook —
   открывать существующий и добавлять/перезаписывать листы):
   - **«Текущие H1-H6»** — выгрузка текущих заголовков: `№, URL, Раздел, Title, H1, H2, H3, H4, H5, H6, Всего заголовков, Проблемы`
     (несколько заголовков одного уровня — через ` | `, если нет — `—`).
   - **«Скорректированные H1-H6»** — создаётся, **если исправлять нужно заголовки практически на всех
     страницах** (системная проблема). Колонки: `№, URL, Раздел, H1, H2, H3, H4, H5, H6, Что изменено`.
     Заголовки подбираются **исходя из имеющегося текста страницы** (смысловые блоки, абзацы-подзаголовки).

## Порядок работы

> **Отчёты о ходе (для прогресс-бара).** Выведи `[[stage:1/3]]` в начале, `[[stage:2/3]]` перед
> анализом заголовков и `[[stage:3/3]]` перед сохранением файлов.

1. **Собрать все URL** — как в пункте 2.1 (и можно переиспользовать подход навыка `seo-metatags-extract`):
   сначала `sitemap.xml` (и индекс), при неполной/битой карте — краулинг по внутренним ссылкам
   (меню, футер, перелинковка). Объединять оба источника, канонизировать (`https` + основной домен),
   исключать технические адреса (`/search/`, `/banners/click/`, `/tags/`, счётчики), файлы и не-200.
2. **На каждой странице** извлечь заголовки `H1`–`H6` в порядке следования и `title`.
3. **Проверить структуру заголовков:**
   - **H1** — есть и ровно один (отсутствует / несколько — проблема).
   - **Вложенность** — нет пропуска уровней (например, H1 → H3); первый заголовок — H1.
   - **Структура** — есть H2 и смысловое членение; текст не свален «одним H1».
   - **Качество** — нет дублей, пустых и слишком длинных заголовков (условно > 80 знаков),
     заголовки не свёрстаны картинками/стилями.
   - **Смысл** — H1 отражает главную тему и содержит основной запрос; H2–H3 раскрывают подтемы.
4. **Сформировать** `.docx` и листы XLSX (см. «Техника»).

### Когда создавать лист «Скорректированные H1-H6»
Если правки нужны почти на всех страницах (условно ≥ 80% страниц) — проблема системная, и в таблице
делаются оба листа: «Текущие H1-H6» и «Скорректированные H1-H6», чтобы было видно, какие теги и куда
ставить на каждой странице. Скорректированные заголовки строятся из уже имеющегося текста: H1 — тема
страницы, H2–H3 — по смысловым блокам/абзацам-подзаголовкам. Дополнительно пройдись по листу и уточни
формулировки, если автоматический вариант получился неточным.

## Структура .docx
- Обложка (название 24pt #333333, дата 9pt #942972, таблица проекта).
- `Heading 1` — «Анализ страничных факторов», `Heading 2` — «2.2. Оформление текста».
- **Подводка** — зачем нужна структура текста и корректные заголовки H1–H6.
- **«В ходе проверки выявлены следующие проблемы:»** — тезисно (H1, вложенность, структура, качество).
- **«Рекомендация:»** — тезисно (один H1, иерархия без пропусков, ключи в заголовках, без «заголовков ради выделения»).
- Таблица «Примеры страниц с проблемами заголовков» (Страница / Текущие заголовки / Проблема / Скорректированный H1).

## Техника

Готовый скрипт: `scripts/heading_audit.py`. Запуск:

```bash
python3 scripts/heading_audit.py --url https://<host>/ --out-dir <папка результатов>
```

Скрипт сам: собирает URL, извлекает H1–H6 и title, находит проблемы, формирует листы
«Текущие H1-H6» и (при системной проблеме) «Скорректированные H1-H6» в `Контент_<хост>.xlsx`,
сохраняет `Оформление текста.docx`.
Зависимости: `pip3 install --break-system-packages requests beautifulsoup4 openpyxl python-docx`.

## Что НЕ относится к пункту 2.2
- Текст как таковой (уникальность, вода, переспам, объём) — пункт 2.1.
- Служебные теги (title, description, canonical) — пункт 2.3.
- Изображения — 2.4; исходящие ссылки — 2.5; микроразметка — 2.6.
- Адресация/дубликаты/индексация/перелинковка — пункты 1.1–1.5.
