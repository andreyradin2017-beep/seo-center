# SEO-генерация тем для статей

Задача: сгенерировать уникальные темы для статей по сайту, собрать по ним семантическое ядро с частотностью Wordstat (Россия), сохранить итог в XLSX и CSV.

Навык оптимизирован для повторных запусков по одному проекту: всё, что не меняется (sitemap, бренд-контекст, существующие статьи, конкуренты), кэшируется и перепроверяется раз в месяц. Темы из прошлых запусков накапливаются, чтобы новые генерации не пересекались со старыми.

## Параметры из чата

- `url` — адрес сайта (обязателен)
- `count` — количество тем (по умолчанию 10, диапазон 1–50)
- `competitors` — опционально, список URL конкурентов (массив). **Если передан — всегда имеет приоритет** над кэшем: эти конкуренты используются и запоминаются в кэше для будущих запусков. Если не указан — берутся из кэша, а при его отсутствии/устаревании ищутся через **Яндекс-поиск**.
- `account` — опционально, логин в Яндекс (телефон/e-mail). Если передан — при открытии окна авторизации Wordstat (`--renew`) подставь его в поле входа автоматически, пользователь введёт только SMS-код.
- Опционально: `site_notes` — контекст от пользователя (ниша, ЦА, пожелания, акценты)
- Опционально: `outDir` — папка результатов для датированного запуска (если задана плагином — сохраняй туда; иначе папка проекта).

## Структура данных

### Стабильный кэш (не зависит от даты запуска)

```
.opencode/brand-context/<host>.json    # бренд-контекст (url, company, created_at, checked_at)
.opencode/seo-cache/<host>/
├── sitemap.json            # все URL из sitemap (checked_at)
├── existing-articles.json  # существующие статьи блога (checked_at)
├── competitors.json        # найденные/указанные конкуренты + как раскрывают темы (checked_at)
├── used-topics.json        # НАКОПЛЕННЫЕ темы всех прошлых запусков (никогда не перезаписывается, только дополняется)
└── wordstat-by-query.tsv   # мастер-кэш частотностей: <запрос> \t <частота> \t <checked_at> (ключ — ТЕКСТ запроса)
```

### Рабочая папка запуска (`outDir`)

```
<outDir>/                     # по умолчанию seo-content/<host>/; плагин передаёт seo-results/<host>/<дата_время>/topics/
├── Темы_для_блога_<host>.xlsx  # ИТОГОВАЯ таблица (основной результат)
├── Темы_для_блога_<host>.csv   # копия для Excel/предпросмотра
└── _raw/                     # все промежуточные/рабочие файлы — сюда, не в корень:
    ├── topics-candidates.json  # кандидатные темы + семядро
    ├── topics-structured.json  # темы + H2-структуры + конкуренты + оценка уникальности
    ├── wordstat-queries.tsv    # все запросы для Wordstat (idx, тема, запрос)
    └── wordstat/
        └── frequencies.tsv     # собранные частотности (idx, запрос, тема, частота)
# Исторические серии Wordstat по месяцам навыку тем НЕ нужны — только частотности.
# В корне outDir держи ТОЛЬКО итоговые Темы_для_блога_<host>.xlsx и .csv.
```

## Скорость (важно, читать перед стартом)

Навык должен заканчиваться за минуты, а не десятки минут. Правила:

1. **Сначала кэш, потом сеть.** На каждом шаге (sitemap, бренд-контекст, статьи, конкуренты, Wordstat) проверяй кэш. Если он свежий (< 30 дней) — не делай ни одного сетевого запроса.
2. **Скачивай страницы параллельно.** Используй 8–12 потоков (`ThreadPoolExecutor` / `concurrent.futures`), не обходи по одной.
3. **Не перекачивай уже собранное.** Мастер-кэш частотностей — `.opencode/seo-cache/<host>/wordstat-by-query.tsv` (ключ — **текст запроса**, а не номер строки). Перед сбором засей `frequencies.tsv` известными запросами (`seed-wordstat`), потом докачай только новые и слей результат обратно (`save-wordstat`). Так повторные запросы между запусками не уходят в Яндекс.
4. **Wordstat параллельно и пачками.** Запускай сбор с `--concurrency 5 --rate 4 --summary` (пачками по 60–120 запросов). Флаг `--summary` не создаёт сводный документ с историческими сериями — навыку тем нужны только частотности. Собирай головные запросы (ВЧ/СЧ) в первую очередь.
5. **Один проход парсинга.** HTML страниц парси один раз и сохраняй результат в кэш, а не перечитывай.
6. **Не спавни лишний браузер.** Wordstat-сессию перехватывай только если `api-session.json` отсутствует или протухла (сессия переиспользуется из `.opencode/skills/wordstat/api-session.json`).
7. **Пропускай тяжёлое, когда можно.** Если `competitors` заданы пользователем или есть в кэше — не выполняй поиск. Если темы уже покрывают нишу и запросы известны — не ходи в поиск повторно.
8. **Целевой бюджет:** при прогретом кэше повторный запуск должен укладываться в ~1–2 минуты (в основном — Wordstat по новым запросам).
9. **Меньше мелких шагов.** Используй скрипт `scripts/pipeline.py` для механической части (сборка CSV/XLSX, слияние кэша, обновление used-topics) — это один вызов вместо десятков inline-Python блоков. Не перечитывай одни и те же файлы повторно.

## Скрипты навыка

Каталог `scripts/` рядом с этим `SKILL.md`:

- **`pipeline.py`** — механическая часть одним вызовом:
  - `build <topics.json> <outDir> <host> <used_topics.json>` — собрать CSV + XLSX и обновить накопительный кэш тем;
  - `seed-wordstat <master.tsv> <queries.tsv> <out_freq.tsv>` — засеять известные частотности (по запросу) перед сбором;
  - `save-wordstat <freq.tsv> <master.tsv>` — слить собранные частотности в мастер-кэш;
  - `migrate-wordstat <master.tsv> <freq...>` — построить мастер-кэш из старых index-keyed файлов;
  - `stagecheck <freq.tsv>` — сколько запросов с частотностью (быстрая проверка).
- **`to_xlsx.py`** — отдельная конвертация CSV→XLSX (используется внутри `pipeline.py` и при ручной сборке).

## Отчёты о ходе (для прогресс-бара)

Плагин показывает прогресс по этапам. Начиная работу, один раз выведи в чат маркер этапа
`[[stage:1/6]]` и далее перед каждым следующим этапом — `[[stage:N/6]]` (после sitemap — 2/6,
после бренд-контекста — 3/6, после генерации тем — 4/6, после Wordstat — 5/6, после сохранения — 6/6).
Всего 6 этапов: кэш/sitemap → бренд-контекст/статьи → конкуренты → темы/семядро → Wordstat → итоговые файлы.

## Шаги

### 1. Подготовка

1. Извлеки `url`, `count`, `competitors`, `account`, `outDir` из запроса. Если `url` не указан — спроси.
2. `count` ограничь диапазоном 1–50.
3. Определи `host` (нормализуй: без `www`, без финального `/`).
4. Определи рабочую папку: `outDir`, если передан; иначе `seo-content/<host>/`. Создай её.
5. Создай стабильный кэш `.opencode/seo-cache/<host>/` и `.opencode/brand-context/`.
6. Сообщи **`[[stage:1/6]]`**.

### 2. Sitemap (кэш + перепроверка раз в месяц)

Кэш: `.opencode/seo-cache/<host>/sitemap.json` — плоский массив URL (можно сохранить `{urls, checked_at}`).

1. Если кэш есть и `checked_at` свежее 30 дней — переиспользуй как есть, сеть не трогай.
2. Иначе загрузи sitemap:
   - Попробуй по порядку: `<url>/sitemap.xml`, `<url>/sitemap_index.xml`, `<url>/sitemap/sitemap.xml`.
   - Если sitemap не найден — скачай `robots.txt`, возьми URL из `Sitemap:` строк.
   - Если sitemap — индекс (содержит `<sitemap>`), **параллельно** загрузи все вложенные и объедини.
3. Извлеки все `<loc>` в плоский массив URL. Отфильтруй мусор (параметры сортировки, якоря, служебные файлы).
4. Сохрани в кэш с `checked_at = <сейчас>`, выведи количество URL в чат.
5. Если sitemap совсем не найден — **краулинг** по внутренним ссылкам с главной (очередь BFS, 8–12 потоков, лимит 5000 страниц) и попроси пользователя подтвердить, если сайт очень большой.
6. Перед следующим этапом — **`[[stage:2/6]]`**.

### 3. Бренд-контекст (стабильный кэш, перепроверка раз в месяц)

Кэш: `.opencode/brand-context/<host>.json` — поля `url`, `company`, `created_at`, `checked_at` + фактура.

1. Прочитай `.opencode/brand-context/<host>.json` (если нет — проверь старый путь `seo-content/<host>/brand-context.json` и перенеси в новый кэш).
2. **Переиспользуй как есть**, если файл существует, `url`/`company` совпадают и `checked_at` не старше **30 дней**. Сетевых запросов не делай.
3. **Собери и сохрани**, если файла нет: выбери 5–8 важных страниц из sitemap (главная, о компании, услуги/продукты, экспертные статьи, УТП), скачай **параллельно**, извлеки навигацию, продукты, CTA, контакты, тон, ключевые слова ниши. Сохрани с `created_at` и `checked_at`.
4. **Перепроверь (раз в месяц)**, если `checked_at` старше 30 дней: снова просмотри ключевые страницы (5–8, параллельно), обнови изменившиеся поля, `checked_at = <сейчас>`. Кратко отметь в сводке, что изменилось.
5. `created_at` — когда собран впервые; `checked_at` — когда последний раз сверялся. «Месяц» считается от `checked_at`.
6. Перед следующим этапом — **`[[stage:3/6]]`**.

### 4. Существующие статьи (кэш + перепроверка раз в месяц)

Кэш: `.opencode/seo-cache/<host>/existing-articles.json`.

1. Если кэш есть и `checked_at` свежее 30 дней — переиспользуй, не пересобирай.
2. Иначе:
   - Отфильтруй sitemap, оставив контентные URL (`/blog/`, `/news/`, `/media-center/`, `/articles/`, `/stati/`, `/press/`, `/guides/`, `/help/`, `/cases/`).
   - **Найди блок статей/блога на сайте**: определи объединяющий раздел. Если в sitemap нет явного блога — пройдись по главной и внутренним страницам и найди раздел статей.
   - Скачай HTML **параллельно** (8–12 потоков, максимум 60 страниц), извлеки `title` и `h1`.
   - Выведи в чат: «Блок статей: <раздел>, найдено <N> материалов».
3. Сохрани с `checked_at = <сейчас>`.
4. Перед следующим этапом — **`[[stage:4/6]]`**.

### 5. Учёт прошлых тем (обязательно, ключ к уникальности между запусками)

Кэш: `.opencode/seo-cache/<host>/used-topics.json` — накопительный список всех тем, которые уже генерировались для этого сайта.

1. Прочитай `used-topics.json`, если он есть. Формат: массив объектов `{topic, keywords[], created_at, outDir}`.
2. **Никогда не перезаписывай этот файл целиком** — только дополняй новыми темами после успешной генерации.
3. При генерации новых тем **исключай** пересечения с:
   - темами из `used-topics.json` (по смыслу и по ключевым запросам, а не только дословно);
   - темами из `existing-articles.json` (статьи, уже опубликованные на сайте).
4. После записи итоговой таблицы добавь сгенерированные темы в `used-topics.json` с текущей датой и `outDir`. Дубликаты не добавляй.

### 6. Генерация кандидатных тем

1. Возьми бренд-контекст, существующие статьи и `used-topics.json`.
2. Сгенерируй `count` уникальных тем. Для каждой:
   - **topic** — заголовок статьи
   - **keywords** — 6–11 запросов из семантического ядра, **равномерно распределённых по частотности** (без перекоса в одну группу). **Сверхширокие запросы с частотностью выше 30 000 показов/мес не берём** (они размывают тему и не отражают спрос):
     - ВЧ — высокочастотные: **от 10 000 до 30 000** показов/мес — **2–3 запроса**
     - СЧ — среднечастотные: **от 1 000 до 10 000** — **2–4 запроса**
     - НЧ — низкочастотные: **от 100 до 1 000** (иногда меньше 100, но с реальным спросом) — **2–4 запроса**
     - Итог: 6–11 запросов на тему (например 3 ВЧ + 4 СЧ + 4 НЧ = 11). Верхняя граница частотности — **30 000**.
   - **intent** — informational / commercial / transactional
   - **why_unique** — почему темы нет на сайте и в прошлых запусках, чем отличается от конкурентов
3. Критерии:
   - ✅ Никаких дублей и семантических пересечений с `existing-articles.json` и `used-topics.json`
   - ✅ Запросы должны иметь реальный спрос (Wordstat, Россия)
   - ✅ Тема связана с продуктами/нишей сайта, чётко разбивается на H2
4. Сохрани в `topics-candidates.json`.

### 7. Проверка конкурентов и уникальности (кэш конкурентов с памятью)

Кэш: `.opencode/seo-cache/<host>/competitors.json` — **память по конкурентам, переиспользуется между запусками**.

1. **Приоритет источников — строго по порядку:**
   - **Пользователь передал `competitors`** — это высший приоритет. Используй ровно эти URL (даже если кэш отличается) и **обнови кэш**: сохрани новые URL с пометкой `source: "user"` и `checked_at`. При следующем запуске без явного списка эти пользовательские конкуренты переиспользуются из кэша.
   - **Кэш свежий (< 30 дней)** — переиспользуй сохранённых конкурентов и результат их разбора, **без выхода в сеть**.
   - **Иначе — поиск.** Найди 2–4 сайта и сохрани в кэш с `checked_at`.
2. **Поиск выполняй в Яндексе, а не в Bing.** Используй Яндекс-поиск (`https://yandex.ru/search/?text=<запрос>`, запрос URL-encoded, `User-Agent` браузера) или MCP-браузер Playwright, если доступен. Bing/Google в этой среде дают нерелевантную выдачу или блокируют автоматические запросы. Если Яндекс отдал капчу — открой поиск через Playwright-браузер и считай домены из выдачи.
3. Изучи, как тема раскрыта у конкурентов (скачай 1–2 их статьи по теме, параллельно).
4. Сформулируй, чем статья сайта будет отличаться (по каждой теме).
5. Сохрани в `topics-structured.json` поля: `topic`, `structure` (список H2), `keywords`, `competitors`, `why_unique`, `novelty_score` (ВЫСОКАЯ / СРЕДНЯЯ-ВЫСОКАЯ / СРЕДНЯЯ).
6. Перед следующим этапом — **`[[stage:5/6]]`**.

### 8. Сбор частотностей Wordstat

#### 8.1. Подготовка запросов

1. Из `topics-candidates.json` вытащи все ключевые слова.
2. Сохрани в `wordstat-queries.tsv` (табуляция): `индекс \t тема \t запрос`.

#### 8.2. Запуск сбора через JSON API Яндекса

Используй скрипт навыка `wordstat` — **`.opencode/skills/wordstat/wordstat-api.js`** (внутренний JSON API `POST https://wordstat.yandex.ru/wordstat/api/getGraph`, окно браузера не открывается, капча не появляется).

1. Проверь, что рядом со скриптом есть `api-session.json`. Если файла нет или сессия протухла — запусти `--renew` один раз:
   ```bash
   node .opencode/skills/wordstat/wordstat-api.js <wordstat-queries.tsv> --renew
   ```
   Если передан `account` (логин/телефон) — **автоматически подставь его в поле входа** (`input[autocomplete="tel"]`, `input[name="login"]`, `input[placeholder*="телефон"]`), пользователю останется ввести SMS-код. После входа введи любой запрос и открой вкладку «Динамика».
2. Собери частотности (окно больше не открывается). Сначала засей рабочую `frequencies.tsv` известными запросами из мастер-кэша, затем запусти сбор — он пропустит засеянные индексы и докачает только новые. После — слей результат в мастер-кэш.
   ```bash
   # 1) засеять известные запросы (по тексту, не по индексу)
   python3 .opencode/skills/seo-topics/scripts/pipeline.py seed-wordstat \
       .opencode/seo-cache/<host>/wordstat-by-query.tsv \
       <wordstat-queries.tsv> <outDir>/wordstat/frequencies.tsv
   # 2) докачать новые (уже собранные индексы скрипт пропустит).
   #    --summary: не создавать сводный документ с историческими сериями —
   #    навыку тем нужны только частотности (быстрее и без лишних файлов).
   node .opencode/skills/wordstat/wordstat-api.js <wordstat-queries.tsv> \
       --graphType month --concurrency 5 --rate 4 --summary \
       --out <outDir>/wordstat/frequencies.tsv
   # 3) слить всё обратно в мастер-кэш (ключ — запрос)
   python3 .opencode/skills/seo-topics/scripts/pipeline.py save-wordstat \
       <outDir>/wordstat/frequencies.tsv .opencode/seo-cache/<host>/wordstat-by-query.tsv
   ```
   Если мастер-кэша ещё нет, а есть старые index-keyed `frequencies.tsv` — построй его: `pipeline.py migrate-wordstat <master.tsv> <freq1.tsv> [freq2.tsv ...]`.
3. Скрипт поддерживает флаг параллельности `--concurrency N` (1–8) и `--rate R` (запросов/сек). Для тем используй `--concurrency 5 --rate 4`. На практике 20 запросов собираются за ~5 секунд. При ошибках ставит `error`/`auth_error`. Повторные нули не пересобирай — они окончательные; уже собранные индексы скрипт пропускает сам (докачка).
4. Сообщи в чат, сколько запросов обработано и сколько имеют нулевую частотность.
5. Перед следующим этапом — **`[[stage:6/6]]`**.

#### 8.3. Анализ частотностей

1. Проанализируй `frequencies.tsv`.
2. Темы, где **ни один запрос** не имеет частотности — убери из итоговой таблицы, предупреди пользователя.
3. Запросы с нулевой частотностью и запросы **с частотностью выше 30 000** внутри темы — убери из итоговой ячейки. Если после чистки в теме меньше 6 запросов (нижней границы диапазона 6–11) — добери замену (новые ВЧ/СЧ/НЧ-запросы по теме) и пересобери только их.

### 9. Формирование итоговой таблицы

Итоговый результат — **XLSX** (основной) + CSV-копия.

#### Формат таблицы

Колонки (строго 3):
```
Название статьи;Структура;Запросы из сем ядра
```

- **Название статьи** — тема как есть.
- **Структура** — все H2 через `|` (каждый H2 с новой строки внутри ячейки).
- **Запросы из сем ядра** — каждый запрос с частотностью (формат `запрос частотность`), каждый с новой строки внутри ячейки. Запросы с нулевой частотностью убрать.

Примеры ячеек:
```
Структура:
Что такое меланома и чем она опасна
Факторы риска: родинки, солнце, наследственность
Первые признаки меланомы: правило ABCDE

Запросы из сем ядра:
меланома 178 074
меланома кожи 26 031
меланома симптомы 6 437
```

#### Сохранение

Используй готовый скрипт навыка — он делает всю механическую часть **одним вызовом** (CSV + XLSX + обновление накопительного кэша), чтобы не тратить время на десятки мелких шагов:

```bash
python3 .opencode/skills/seo-topics/scripts/pipeline.py build \
  <outDir>/topics-candidates.json <outDir> <host> .opencode/seo-cache/<host>/used-topics.json
```

Скрипт создаёт `Темы_для_блога_<host>.csv` и `Темы_для_блога_<host>.xlsx` (перенос строк, авто-ширина), затем добавляет новые темы в `used-topics.json` без дублей. Если `openpyxl` недоступен — XLSX создай через LibreOffice headless:

```bash
soffice --headless --convert-to xlsx:"Calc MS Excel 2007 XML" \
  --infilter="Text - txt - csv (StarCalc):59,34,76,1,,0,false,true,true,false,false,-1" \
  "<outDir>/Темы_для_блога_<host>.csv" --outdir <outDir>
```

Другие подкоманды скрипта:
- `pipeline.py merge-wordstat <cache_freq.tsv> <outDir>/wordstat/frequencies.tsv` — слить общий кэш частотностей в рабочую папку;
- `pipeline.py stagecheck <freq.tsv>` — быстрая проверка, сколько запросов с частотностью.

После сборки выведи в чат таблицу **обновлённых тем** и пути к файлам XLSX и CSV.

### 10. Сводка в чате

Выведи:
- URL сайта, число тем, число запросов в семядре.
- Пути к файлам (XLSX — основной, CSV).
- Краткую таблицу: тема → частотность головного запроса.
- Отметки кэша: что переиспользовано, что собрано нового, что перепроверено (обновлено за месяц), какие темы убраны из-за нулевой частотности.
