# Технический аудит сайта (методология «Текарт»)

## Результаты пункта 2.5

1. **`Исходящие ссылки.docx`** — отчёт: подводка (зачем учитывать исходящие ссылки), тезисно проблемы,
   тезисно рекомендации, таблица доменов с решением.
2. Листы в **общей таблице по контенту `Контент_<хост>.xlsx`** (открывать существующий):
   - **«Исходящие ссылки»** — по страницам и доменам: `№, Страница, Домен, Тип, Ссылок, rel, target=_blank без noopener, Пример анкора, Индексация, Рекомендация`;
   - **«Рекомендации по ссылкам»** — по доменам: `№, Домен, Тип, Ссылок, Страниц, nofollow, dofollow, blank без noopener, Индексация, Рекомендация`.

## Логика решения (главное)

- **Свои ресурсы** (поддомены и проекты компании, например `contacts.roysol.ru`) — **не закрывать**:
  вес остаётся внутри экосистемы.
- **Сторонние внешние ссылки**, ненужные пользователю, — **закрывать `rel="nofollow"`**, чтобы не
  отдавать ссылочный вес; для рекламных/партнёрских — `rel="sponsored"`.
- **Ссылочные «облака» и виджет-ссылки в футере** (сквозные, на всех страницах) — **убрать или закрыть nofollow**;
  это самый сильный источник потерь веса.
- **Счётчики/аналитика** — оставить, но ссылковую часть закрыть `nofollow`.
- **Полезные тематические ссылки** (партнёры, официальные ресурсы, источники) можно оставлять `dofollow` —
  они работают на доверие; достаточно убрать нерелевантные и сомнительные.
- Для всех ссылок `target="_blank"` добавить `rel="noopener"`.

## Порядок работы

> **Отчёты о ходе (для прогресс-бара).** Выведи `[[stage:1/3]]` в начале, `[[stage:2/3]]` перед
> анализом ссылок и `[[stage:3/3]]` перед сохранением файлов.

1. **Собрать все URL** — как в пунктах 2.1–2.4 (sitemap.xml + краулинг по перелинковке).
2. **На каждой странице собрать все `<a href>` с внешним доменом** (кроме самой страницы/хоста): URL,
   анкор, `rel`, `target`.
3. **Классифицировать** каждый домен: свой ресурс / счётчик-аналитика / виджет-ссылки / соцсети / прочий внешний.
4. **Определить решение** по каждому домену (закрывать от индексации или нет) — по логике выше.
5. **Сформировать** `.docx` и листы XLSX.

## Структура .docx
- Обложка (название 24pt #333333, дата 9pt #942972, таблица проекта).
- `Heading 1` — «Анализ страничных факторов», `Heading 2` — «2.5. Исходящие ссылки».
- **Подводка** — зачем учитывать исходящие ссылки (размывание веса, злоупотребления, сквозные ссылки).
- **«В ходе проверки выявлены следующие проблемы:»** — тезисно (всего ссылок, dofollow/nofollow, облака, счётчики, noopener).
- **«Рекомендация:»** — тезисно (свои — не закрывать; чужие — nofollow/sponsored; облака — убрать; счётчики — nofollow; noopener).
- Таблица «Внешние ссылки по доменам и решение».

## Техника

Готовый скрипт: `scripts/outlink_audit.py`. Запуск:

```bash
python3 scripts/outlink_audit.py --url https://<host>/ --out-dir <папка результатов>
```

Скрипт сам: собирает URL, извлекает внешние ссылки, классифицирует домены, считает dofollow/nofollow,
находит ссылочные «облака» и отсутствие noopener, пишет листы «Исходящие ссылки» и «Рекомендации по ссылкам»
в `Контент_<хост>.xlsx` и сохраняет `Исходящие ссылки.docx`.
Зависимости: `pip3 install --break-system-packages requests beautifulsoup4 openpyxl python-docx`.

## ОБЯЗАТЕЛЬНЫЕ ПРАВКИ ДМИТРИЯ (обязательно)
- НЕ писать про аналитику/счётчики (Яндекс.Метрика и т.п.) и «ссылочные облака» — эти блоки убрать.

- Не писать про `rel="sponsored"`.
- Ссылки указывать полными URL.
