# Технический аудит сайта (методология «Текарт»)

Проводим технический SEO-аудит сайта и оформляем результаты в `.docx` и `.xlsx`.

## Результаты пункта 2.1

1. **`Текстовый контент сайта.docx`** — текстовый отчёт: подводка (зачем нужен текстовый контент),
   тезисно выявленные проблемы, тезисно рекомендации (по образцу Frontside.ru), таблица проблемных страниц.
2. **`Контент_<хост>.xlsx`** — **единая таблица по контенту сайта**, где перечислены все страницы сайта.
   - Лист по умолчанию для этого пункта — **«Текстовый контент»**.
   - **Эта же XLSX используется другими пунктами раздела «Анализ страничных факторов»**: каждый следующий
     пункт (оформление текста, служебные теги/метатеги, изображения, исходящие ссылки, микроразметка)
     добавляется **отдельным листом** в этот же файл. Не создавай новый workbook — открывай существующий
     `Контент_<хост>.xlsx` и добавляй/перезаписывай свой лист.

## Порядок работы

> **Отчёты о ходе (для прогресс-бара).** Выведи `[[stage:1/3]]` в начале, `[[stage:2/3]]` перед анализом
> контента и `[[stage:3/3]]` перед сохранением файлов.

1. **Собрать все URL сайта.** Сначала `sitemap.xml` (и варианты `/sitemap_index.xml`, `/sitemap/`); если
   карты нет, она неполная или битая — обойти сайт по внутренним ссылкам (меню, футер, перелинковка).
   Объединять оба источника. Приводить адреса к каноническому виду (`https` + основной домен), исключать
   технические адреса (`/search/`, `/banners/click/`, `/tags/`, счётчики), файлы (pdf/xls/картинки) и
   страницы с откликом не 200.
2. **Зайти на каждую страницу** и извлечь основной текст (без меню/футера/сайдбаров).
3. **Посчитать метрики по каждой странице:**
   - **Объём** — знаков и слов.
   - **Уникальность** — в первую очередь внутренняя (пересечение текстов между страницами сайта: шинглы
     + коэффициент Жаккара). Внешнюю уникальность офлайн не измерить — при необходимости отметить, что
     нужна проверка через text.ru / Advego.
   - **Вода** — доля стоп-слов и «водяных» оборотов («стоит отметить», «широкий ассортимент» и т.п.).
   - **Переспам** — частота повторения топ-слова (признак переоптимизации).
   - **Частота публикации информационного контента** — по разделу новостей/блога/статей: число публикаций,
     даты, регулярность (публикаций в месяц).
4. **Сформировать** `.docx` и `.xlsx` (см. раздел «Техника»).

### Ориентиры (пороги)
- Объём: < 1500 знаков — мало; < 800 — очень мало. Ориентир: ≥ 1500–2000 (коммерческие), ≥ 3000–5000 (информационные).
- Уникальность (внутренняя): < 70% — низкая (шаблонные/пересекающиеся тексты).
- Вода: > 18% — много воды.
- Переспам: доля топ-слова > 5% — переспам.
- Информационный контент: редкие публикации (< 1–2 в месяц) или отсутствие раздела — проблема.

## Структура .docx

- Обложка: название (24pt, #333333), дата (9pt, #942972), таблица проекта (Заказчик / Документ), стиль `Table Grid`.
- `Heading 1` — «Анализ страничных факторов»; `Heading 2` — «2.1. Текстовый контент сайта».
- **Подводка** — зачем вообще текстовый контент для SEO.
- **«В ходе проверки выявлены следующие проблемы:»** — тезисно, по пунктам (объём, уникальность, вода,
  переспам, информационный контент и частота публикаций).
- **«Рекомендация:»** — тезисно, по пунктам (уникализация, объём, вода, переспам, регулярный контент, FAQ,
  работа с общей XLSX).
- Таблица «Страницы, требующие доработки текста» (Страница / Объём / Вода / Переспам / Примечание).

## Техника

Готовый скрипт: `scripts/content_audit.py` (тот же каталог, что и этот SKILL.md). Запуск:

```bash
python3 scripts/content_audit.py --url https://<host>/ --out-dir <папка результатов>
```

Скрипт сам: собирает URL (sitemap + краулинг), парсит основной текст, считает метрики, сохраняет
`Текстовый контент сайта.docx` и `Контент_<хост>.xlsx` (лист «Текстовый контент»).
Зависимости при необходимости: `pip3 install --break-system-packages requests beautifulsoup4 openpyxl python-docx`.

Если сайт крупный/нестандартный — можно дописать/адаптировать скрипт, но обязательно сохранить формат вывода
(единый `.docx` + лист в общей `Контент_<хост>.xlsx`).

## Что НЕ относится к пункту 2.1
- Оформление текста (заголовки, выделения, списки) — пункт 2.2.
- Служебные теги (title, description, canonical и т.п.) — пункт 2.3.
- Изображения — пункт 2.4.
- Исходящие ссылки — пункт 2.5.
- Микроразметка — пункт 2.6.
- Адресация, дубликаты, индексация, перелинковка — пункты 1.1–1.5.

## Глубина проверки (крупные сайты)
Если на сайте много страниц (условно > 200), проверяй **выборочно** — самые важные/популярные страницы (главная, каталоги/разделы, карточки товаров/услуг, несколько статей), чтобы сделать вывод о состоянии сайта. В SEO-центре это задаётся полем «Глубина проверки, страниц» (по умолчанию 50) и передаётся в скрипт параметром `--limit N`. Если указано больше 1000 или больше числа страниц — проверяются все страницы (предупреди, что это займёт много времени).

## ОБЯЗАТЕЛЬНЫЕ ПРАВКИ ДМИТРИЯ (обязательно)
- Указывать, СКОЛЬКО страниц проверено.
- Учитывать информационные страницы (например, раздел «энциклопедия»), чтобы был понятен расчёт среднего объёма.
- Положительное — отдельным блоком; не выносить не-проблемы.
- Если рекомендуешь — давать 1 буквальный пример.
- Не обрывать фразы посреди слова.
