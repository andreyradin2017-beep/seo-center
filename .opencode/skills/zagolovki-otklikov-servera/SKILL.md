# Технический аудит сайта (методология «Текарт»)

Проводим технический SEO аудит сайта и оформляем результаты в `.docx` по заданному шаблону.

## Формат итогового документа

- Обложка: название аудита (24pt, #333333), дата (9pt, #942972), таблица данных проекта (Заказчик / Документ). Без брендинга «Текарт» — без копирайта, дисклеймера и контактов менеджера.
- «Содержание» — список разделов.
- Заголовки: Heading 1 / Heading 2 / Heading 3.
- Каждый подраздел: констатация фактов → недостатки с примерами → блок «Рекомендация:» жирным.

## Язык и стиль

- Понятный русский язык, без воды.
- Рекомендации — чёткие, по пунктам.
- Нейтральный экспертный деловой тон.

## Шаг 0. Единый сбор данных (общий коллектор)

Перед анализом запусти общий краулер-коллектор — один обход собирает данные для всех модельных пунктов и кэширует результат:

```bash
python3 .opencode/tools/seo_collect/site_collect.py --url <URL сайта>
```

Скрипт печатает путь к JSON (строка `OUT=...`, по умолчанию `/tmp/opencode/seo_collect/<хост>.json`) и кэширует его на 2 часа. Дальше данные бери из JSON скриптом на Python — сайт повторно вручную НЕ обходи.

Что в JSON:
- `pages[]` — по каждой странице: `status`, `final_url`, `redirect_chain`, `title`, `description`, `meta_robots`, `canonical`, `lang`, `headings` (H1–H6), `h1`, `text`, `text_len`, `og`, `twitter`, `jsonld_types`, `jsonld_blocks`, `microdata_types`, `structured_types`, `links_internal` (абсолютные URL), `links_external`, `images`, `soft404`;
- `internal_link_status` — отклик каждой внутренней ссылки (`status`, `location`);
- `sitemap` (`found`, `urls`, `files`), `robots` (`status`, `text`), `external_links`, `stats`.

Ключи: `--refresh` — пересобрать кэш; `--limit N` — ограничить число страниц; `--no-link-check` — без проверки откликов ссылок (быстрее).

## Порядок работы по пункту 1.3 «Заголовки откликов сервера»

> **Отчёты о ходе (для прогресс-бара).** При запуске из плагина выведи `[[stage:1/3]]` в начале, `[[stage:2/3]]` перед проверкой откликов и `[[stage:3/3]]` перед формированием `.docx`.

**Задача:** найти все страницы сайта, которые встречаются **во внутренней перелинковке** (в ссылках `<a href>` на страницах сайта), прогнать их и узнать код отклика сервера. В отчёт попадают только ссылки с откликом **не 200**.

Действовать строго по шагам:

1. Заходим на сайт. Обходим его по внутренним ссылкам (краулинг от главной и из меню), собирая **все внутренние ссылки** (`<a href>`) вместе с URL страницы-источника, где эта ссылка встречается.
   - Проверяем именно внутренние ссылки (перелинковку), а не только `sitemap.xml`. Внешние ссылки и картинки не берём.
2. Для каждой уникальной ссылки-цели определяем **код отклика сервера** (без следования редиректам, чтобы увидеть реальный код: 200, 301, 302, 401, 403, 404, 410, 5xx).
3. Оставляем только цели с откликом **не 200**. Страницы с 200 в отчёт не попадают.
4. Для каждой не-200 ссылки фиксируем: сам URL, страницу(ы)-источник («URL на странице»), код отклика и рекомендацию по исправлению.
5. Оформляем раздел в структуре:
   - **подводка** — зачем поддерживать отклики сервера в корректном виде;
   - **ответы сервера в перелинковке, которые отдают не 200** — таблица;
   - **рекомендации по исправлению** — можно также таблицей.

### Таблица
Заголовок: «Таблица N. Отклики сервера в перелинковке (не 200)».
Колонки:
| URL | URL на странице | Отклик | Рекомендация |
- «URL на странице» — адрес страницы-источника, где стоит ссылка. Если ссылка в шаблоне и встречается на всех страницах сайта — так и указать (например «Все страницы сайта (шаблон меню)»).
- В таблицу включаются **только не-200** отклики.

### Шаблон подводки (адаптировать)
«Коды отклика сервера — базовый сигнал для поисковых роботов: 200 означает, что страница доступна и её можно индексировать, 3xx — перенос адреса, 404/410 — страница не найдена, 401/403 — доступ запрещён, 5xx — ошибка сервера. Если ссылки во внутренней перелинковке ведут на страницы с некорректным откликом, поисковый робот тратит краулинговый бюджет на «мусорные» адреса, не получает ссылочный вес (302 и 404 его не передают), а пользователи попадают на ошибки, что ухудшает поведенческие факторы. Кроме того, неверные коды мешают поисковым системам своевременно исключать битые страницы из индекса и снижают доверие к сайту. Поэтому коды отклика сервера необходимо регулярно проверять и поддерживать в корректном состоянии.»

### Типовые рекомендации
- 404: восстановить страницу по прежнему адресу; если контент перенесён — настроить 301 на новый адрес; если страница не нужна — удалить/заменить ссылку на ней.
- 301/302: для постоянного переноса использовать 301 и, где возможно, заменить ссылки на конечный адрес, чтобы избежать лишних редиректов; для 302 на рабочий адрес — оставить только если это осознанное поведение (счётчики/баннеры).
- 401/403: восстановить доступ (права, авторизация, настройки сервера), чтобы страница отдавала 200.
- 5xx: устранить ошибку сервера (нагрузка, конфиг, ошибки кода).
- Внутренние ссылки вести только на существующие страницы с откликом 200; регулярно перепроверять перелинковку.

## Техника проверки откликов

Использовать `requests` (при необходимости `pip3 install --break-system-packages requests beautifulsoup4`).
- Обходить внутренние ссылки BFS от главной и меню.
- Проверять отклик цели **без следования редиректам** (`allow_redirects=False`), чтобы зафиксировать реальный код.
- Дедуплицировать цели, объединяя страницы-источники.
- Учитывать, что сервер может не поддерживать HEAD — использовать GET.

## Техника генерации .docx

Использовать `python-docx` (`pip3 install --break-system-packages python-docx`).
- `doc.styles['Normal'].font.size = Pt(10)`
- Обложка: заголовок Pt(24) 0x333333; дата Pt(9) 0x942972; таблица данных проекта (3 строки: шапка, «Заказчик», «Документ»), стиль `Table Grid`. Копирайт/дисклеймер/контакты «Текарт» не добавлять.
- Таблица данных проекта: `add_table(4,2)`, стиль `Table Grid`.
- Подраздел: `add_heading('1.3. Заголовки откликов сервера', level=2)`.
- Таблица откликов: заголовок жирным, шапка **«URL» | «URL на странице» | «Отклик» | «Рекомендация»**.
- «Рекомендация:» — `run.bold = True`; списки — стиль `List Bullet`.

После генерации проверить документ через `python-docx` и вывести краткую сводку не-200 откликов.
