# Технический аудит сайта (методология «Текарт»)

Проводим технический SEO аудит сайта и оформляем результаты в `.docx` по заданному шаблону.

## Формат итогового документа

- Обложка: название аудита (24pt, #333333), дата (9pt, #942972), таблица данных проекта (Заказчик / Документ). Без брендинга «Текарт» — без копирайта, дисклеймера и контактов менеджера.
- «Содержание» — список разделов.
- Заголовки: Heading 1 / Heading 2 (1.5) / Heading 3.
- Каждый подраздел: краткая подводка (зачем это нужно с точки зрения SEO) → выявленные проблемы с примерами и ссылками → блок «Рекомендация:» жирным.
- Где нужно — таблицы, списки URL, положительные моменты.

## Язык и стиль

- Понятный русский язык, без воды.
- Рекомендации — чёткие, по пунктам (формат «Проблема N. … → Рекомендация: …»).
- Нейтральный экспертный деловой тон.

## Шаг 0. Единый сбор данных (общий коллектор)

Перед анализом запусти общий краулер-коллектор — один обход собирает граф внутренних ссылок и данные страниц:

```bash
python3 .opencode/tools/seo_collect/site_collect.py --url <URL сайта>
```

Скрипт печатает путь к JSON (строка `OUT=...`, по умолчанию `/tmp/opencode/seo_collect/<хост>.json`) и кэширует его на 2 часа. Дальше данные бери из JSON скриптом на Python — сайт повторно вручную НЕ обходи.

Что в JSON:
- `pages[]` — по каждой странице: `status`, `final_url`, `redirect_chain`, `title`, `description`, `canonical`, `headings` (H1–H6), `text`, `links_internal` (абсолютные URL, дедуп по странице), `links_external`, `images`, `soft404`;
- `internal_link_status` — отклик каждой внутренней ссылки (`status`, `location`);
- `sitemap` (`found`, `urls`, `files`), `robots` (`status`, `text`), `external_links`, `stats`.

Из `links_internal` строй граф: входящие/исходящие, глубина от главной, сквозные ссылки (встречаются почти на всех страницах), «сироты». Ключи: `--refresh` — пересобрать кэш; `--limit N` — ограничить число страниц; `--no-link-check` — быстрее.

## Порядок работы по пункту 1.5 «Внутренняя ссылочная топология»

> **Отчёты о ходе (для прогресс-бара).** При запуске из плагина выведи `[[stage:1/3]]` в начале, `[[stage:2/3]]` перед анализом топологии и `[[stage:3/3]]` перед формированием `.docx`.

**Задача:** оценить структуру сайта (логику, вложенность разделов и внутреннюю перелинковку), выявить проблемы и дать рекомендации.

Действовать строго по шагам:

1. Заходим на сайт. Обходим его по внутренним ссылкам (краулинг от главной, из меню и футера), собирая граф внутренних ссылок: для каждой страницы — глубину (число кликов от главной), страницы-источники, количество входящих и исходящих ссылок, ссылки сквозного меню.
2. Определяем структуру: сколько разделов и подразделов, максимальная глубина, как разделы связаны между собой, какие ссылки сквозные (шаблон), а какие контекстные.
3. Отдельно проверяем типовые аспекты топологии:
   - **Хлебные крошки** — есть ли, ведут ли на родительские разделы, полная ли цепочка (не только «Главная >> страница»), нет ли self-ссылки на текущую страницу.
   - **Вложенность и логика** — соответствует ли структура URL и меню тематике, нет ли «плоской» или, наоборот, избыточно глубокой структуры.
   - **Входящие ссылки / «сироты»** — страницы с 1–3 входящими ссылками, доступные только с одного места; страницы, недостижимые по ссылкам.
   - **Навигация по разделу** — есть ли ссылки на соседние подразделы (боковое меню, «смотрите также»), или со страницы подраздела можно уйти только на уровень выше.
   - **Дублирование меню** — повторяющиеся сквозные ссылки в разных блоках навигации.
   - **Анкоры** — текстовые ли ссылки, осмысленные ли (ссылки-картинки без текста передают сигнал слабее).
   - **HTML-карта сайта** — есть ли, полная ли (все ли разделы и подразделы в неё включены), обновляется ли.
   - **Футер** — есть ли внутренняя навигация в подвале, не перегружен ли он внешними ссылками/виджетами.
   - **Логотип** — ведёт ли на канонический адрес главной (`/`), а не на технический дубль (`/index.htm` и т.п.).
   - **Тематическая связность** — ссылаются ли тематически близкие разделы друг на друга.
4. Для проблем со слабыми входящими ссылками строим таблицу: **«Страница»** | **«Входящих ссылок»** | **«Откуда доступна»**.
5. Оформляем раздел в структуре:
   - **подводка** — что такое внутренняя ссылочная топология и зачем она нужна с точки зрения SEO;
   - **проблемы** — по пунктам, с примерами URL и таблицей «полусирот»;
   - **положительные моменты**;
   - **рекомендация (общая)** — сводный список действий.

### Шаблон подводки (можно адаптировать)
«Внутренняя ссылочная топология — это структура ссылок между страницами сайта. Она определяет, как поисковый робот обходит сайт, как распределяется ссылочный вес между страницами и какие страницы поисковая система считает наиболее важными. Логичная иерархия разделов, сквозная навигация, полные хлебные крошки и контекстные перелинковки помогают роботам быстрее находить и индексировать страницы, понимать тематические связи разделов и передавать вес на приоритетные страницы, а посетителям — легко перемещаться по сайту. Напротив, плоская или запутанная структура, «страницы-сироты» и слабая перелинковка приводят к тому, что важные страницы недополучают вес, медленнее индексируются и хуже ранжируются.»

### Типовые проблемы и рекомендации
- **Усечённые хлебные крошки** → вывести полную цепочку со ссылками на родительские разделы; последний элемент (текущая страница) — без ссылки.
- **Слабые входящие ссылки / «полусироты»** → связать контекстными перелинковками тематически близкие страницы (подразделы между собой, с каталога — на статьи, ГОСТы, услуги).
- **Нет навигации внутри раздела** → добавить боковое меню раздела или блок «Смотрите также».
- **Дублирование сквозного меню** → унифицировать навигацию, не повторять одни и те же ссылки в нескольких блоках.
- **Ссылки-картинки без текстовых анкоров** → добавить текстовые подписи или корректные `alt`, для ключевых разделов — текстовые анкоры.
- **Логотип ведёт на технический дубль** → перевести ссылку на канонический адрес главной `/`.
- **Неполная HTML-карта сайта** → дополнить всеми разделами и подразделами, держать в актуальном состоянии.
- **Перегруженный внешними ссылками футер** → убрать лишние виджеты, добавить внутреннюю навигацию по ключевым разделам.
- **Слабая тематическая связность** → выстроить перелинковку между близкими кластерами с описательными анкорами.

## Техника анализа топологии

Использовать `requests` и `beautifulsoup4` (при необходимости `pip3 install --break-system-packages requests beautifulsoup4`).
- Обходить сайт BFS от главной, собирая для каждой страницы глубину, входящие/исходящие ссылки и ссылки сквозного меню.
- Сквозным считать ссылку, которая встречается в шаблоне (меню/футер) на большинстве страниц; контекстной — ссылку в теле страницы.
- Отличать self-ссылки (например, в хлебных крошках) от реальных входящих.
- Для проверки HTML-карты сравнить её ссылки с полным списком страниц сайта.

## Техника генерации .docx

Использовать `python-docx` (`pip3 install --break-system-packages python-docx`).
- `doc.styles['Normal'].font.size = Pt(10)`
- Обложка: заголовок Pt(24) 0x333333; дата Pt(9) 0x942972; таблица проекта (3 строки: шапка, «Заказчик», «Документ»), стиль `Table Grid`; «Содержание» Pt(20) 0x333333.
- Раздел: `add_heading('1.5. Внутренняя ссылочная топология', level=2)`; при необходимости подпункты — `level=3`.
- Таблица «полусирот»: заголовок жирным, шапка **«Страница» | «Входящих ссылок» | «Откуда доступна»**.
- «Проблема N.» — жирным; «Рекомендация:» — `run.bold = True`; списки — стиль `List Bullet`, итоговый список — `List Number`.

После генерации проверить документ через `python-docx` и вывести краткую сводку проблем топологии.
