# Навык: записка по анализу конкурентов (формат «Текарт»)

Собирает готовый `.docx`-меморандум по конкурентам: **анализ** (краткие выводы по
каждому конкуренту + выводы по рынку) и **рекомендации для внедрения**
(бизнес-идеи, рекомендации для сайта, рекомендации из прошлых аудитов,
маркетинговая активность). К каждой рекомендации прикладывается **скриншот
удачной реализации с ссылкой на источник** в подписи.

Структуру, пояснения и стиль речи берём из **шаблона-эталона** (пример записки
прошлого года по смежному направлению, обычно `.odt`).

## Когда использовать

Пользователь даёт:
- ссылку на таблицу-аудит конкурентов (Google Sheets) и **название вкладки**
  (направление, например «Покраска металлоизделий»);
- данные заказчика (Заказчик, проект-менеджер, месяц документа);
- шаблон-эталон `.odt` прошлого года;
- папку для результатов (`outDir`).

## Правила оформления (обязательные)

- **Имя файла** — по имени задания/направлению, без названия сайта и без слов
  «Технический аудит». Пример: `Аудит конкурентов — Покраска металлоизделий.docx`.
- **Папка результатов** — только `outDir`. Внутри создаём подпапку для скриншотов.
- **Скриншоты.** К **каждой рекомендации, особенно если это доработка сайта**,
  прикладываем скриншот удачной реализации и **ссылку на источник прямо в
  подписи** (формат: `Пример у <кто>: <что>. Источник: <url>`).
  - Если функция есть у конкурентов из таблицы — берём именно их.
  - Если ни у одного из конкурентов из таблицы функции нет — берём удачный
    пример из отрасли и подписываем «Пример в отрасли: … Источник: …».
- **Вкладки браузера** — всегда открываем новую страницу, не трогаем вкладки
  пользователя.
- **Таблицу-источник не редактируем** (только чтение через export).
- **Прогресс** — для длинных задач выводим маркеры `[[stage:N/M]]`.

## Технологии

- **Node.js** (>= 18). Библиотеки: `docx` (генерация .docx), `xlsx` (чтение
  экспорта Google Sheets), `adm-zip` (чтение `.odt`).
- **Playwright** (браузерные инструменты opencode) — для скриншотов.
  Альтернатива без браузера: снипеты `playwright_browser_run_code_unsafe`.

## Установка (один раз на машине)

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
```

(или вручную: `npm install` в папке навыка — поставятся `docx`, `xlsx`, `adm-zip`).

## Порядок работы

> Выведи `[[stage:1/5]]`…`[[stage:5/5]]` по этапам.

### 1. Выгрузить и разобрать таблицу-аудит

```powershell
node scripts/fetch-sheet.mjs "<url-or-id>" "Покраска металлоизделий" --out "<outDir>/_data"
```

Скрипт скачает экспорт `xlsx`, выведет список вкладок и сохранит выбранную
вкладку в `<tab>.txt` и `<tab>.csv`. Если вкладка не указана — покажет список,
чтобы выбрать.

### 2. Разобрать шаблон-эталон

```powershell
node scripts/odt-to-text.mjs "<шаблон-эталон.odt>" "<outDir>/_data/template.txt"
```

Получишь плоский текст с заголовками/таблицами — ориентир по структуре, порядку
разделов и стилю речи.

### 3. Написать контент в формате JSON

Скопируй `templates/content.example.json` в `<outDir>/content.json` и заполни.
Схема:

```
cover        — обложка: topLine, table[{label,value}], title, date, copyright, disclaimer
toc          — массив строк оглавления
section1     — анализ: heading, intro, competitors[], studiedLead, studied[],
               tableNote, summaryTable{caption,headers,rows[][]},
               conclusionsHeading, conclusions[{lead,text}], marketHeading, market[]
section2     — рекомендации: heading, blocks[]
  block      — heading, intro, items[], bullets[], images[]
    item     — title, body, images[{file,caption}]
    bullet   — строка ИЛИ {lead,text}
    image    — {file, caption}   (file — имя файла в screensDir; caption — с ссылкой)
screensDir   — абсолютный путь к папке со скриншотами (в конце слэш)
```

Черновик текста пиши, опираясь на данные таблицы (цифры ИКС/трафика/отзывов,
цены, гарантии, соцсети, реклама, техсостояние) и на эталон. В `summaryTable`
своди ключевые метрики конкурентов; в `conclusions` — по абзацу на конкурента
(жирный лид = имя) + лидер/аутсайдер и «Общие выводы по рынку».

### 4. Собрать скриншоты

Складывай PNG в `screensDir`. Для каждой рекомендации-доработки сайта — скрин
удачной реализации у конкурента/в отрасли. Используй браузерные инструменты
opencode (`playwright_browser_navigate` + `playwright_browser_run_code_unsafe`
для пачки снимков). Строка снимка:

```js
await page.setViewportSize({ width: 1440, height: 900 });
await page.goto(url, { waitUntil: 'domcontentloaded', timeout: 60000 });
await page.waitForTimeout(2500);
await page.screenshot({ path: screensDir + 'NN_name.png' });
```

Подпись всегда содержит ссылку: `Пример у X: …. Источник: https://…`.

### 5. Сгенерировать .docx

```powershell
node scripts/make-docx.mjs "<outDir>/content.json" "<outDir>/<Имя файла>.docx"
```

Готово. Проверь, что файл создан (размер > 0) и открой при необходимости.

## Частые оговорки

- Вкладку Google Sheets можно выгрузить только если доступ «по ссылке»
  (просмотр/редактирование). При закрытом доступе — попросить опубликовать.
- Скриншоты со страниц, закрытых капчей/логином, заменяй аналогом и отмечай это.
- Не переиспользуй один и тот же скрин для двух разных рекомендаций, если это
  заметно; лучше снять отдельный кадр.
