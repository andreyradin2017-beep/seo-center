# Промт для вордстат (общий)

> Скопируй текст целиком, заполни блок «Твои данные» и отправь мне. Работает у любого, у кого установлен Node.js + Playwright (при отсутствии — поставь: `npm i playwright`, затем `npx playwright install chromium`).

## Твои данные

> **Отчёты о ходе (для прогресс-бара).** При запуске из плагина выведи `[[stage:1/3]]` в начале, `[[stage:2/3]]` перед сбором частотностей и `[[stage:3/3]]` перед сохранением CSV.

1. **Список запросов** (замени пункты ниже; можно 1 запрос или 100):
   - заменить_на_запрос_1
   - заменить_на_запрос_2
   - заменить_на_запрос_3
2. **Логин в Яндекс** (номер телефона или e-mail): заменить_на_логин
3. **Период на графике**: последние 2 года (можно указать свой)
4. **Регион**: все регионы (или конкретный, например: Москва)
5. **Устройства**: десктопы (можно: смартфоны / планшеты / все)
6. **Разбивка на графике** (вкладка «Динамика»): по месяцам (можно: по неделям / по дням). Значение передаётся как `month` / `week` / `day`.

## Задача

Собери с [wordstat.yandex.ru](https://wordstat.yandex.ru/) данные вкладки **«Динамика»** (вид `view=graph`) для каждого запроса: выгрузи **число запросов в выбранной разбивке** (по месяцам / по неделям / по дням). Сохрани **один сводный документ на всё задание** (строка — период, колонка — запрос) и покажи сводную таблицу прямо в чате. Отдельные файлы по каждому запросу не создаются.

## Основной способ — через JSON API (без окна с номером телефона)

Используется внутренний API Яндекса `POST https://wordstat.yandex.ru/wordstat/api/getGraph` (JSON). Авторизация и ввод номера телефона нужны **только один раз**, далее всё собирается чисто через HTTP — без браузера и без окна.

Готовый скрипт в этой папке: **`wordstat-api.js`** (рядом с этим файлом).

### Использование

```bash
# 1) ОДИН раз — авторизация + перехват сессии (откроется окно браузера)
node wordstat-api.js <список.tsv> --renew

# 2) Сбор всех запросов — чисто через API, окно не открывается
#    (если api-session.json есть и живая — браузер не запускается вовсе)
node wordstat-api.js <список.tsv> \
    --graphType month \      # month | week | day
    --start 01.09.2024 \     # начало периода (формат ДД.ММ.ГГГГ)
    --end 31.08.2026 \       # конец периода (формат ДД.ММ.ГГГГ)
    --out frequencies.tsv

# 3) Ускоренный сбор (опционально): параллельные запросы + контроль темпа
node wordstat-api.js <список.tsv> \
    --concurrency 5 \        # число параллельных запросов (1–8, по умолчанию 1)
    --rate 3 \               # запросов в секунду суммарно (по умолчанию ~0.8 = пауза 1.2 с)
    --out frequencies.tsv
```

- `<список.tsv>` — файл со строками `id<TAB>заголовок<TAB>запрос` (или просто список запросов по одному в строке). Можно вместо файла передать `--queries "запрос1\nзапрос2\nзапрос3"`.
- При `--renew` открывается окно браузера (профиль `pw-profile`): пользователь входит по номеру телефона, вводит любой запрос и открывает вкладку «Динамика». Реальный запрос `getGraph` (URL, cookies, тело) перехватывается и сохраняется в `api-session.json`. **Это единственный шаг с окном.**
- После этого все запуски идут напрямую в API с сохранённой сессией. Если сессия протухла — выводится `auth_error`, нужен `--renew`.
- **Фоновый режим (без окон на экране):** обычный сбор окно не открывает вообще. Чтобы и окно `--renew` не появлялось, запусти его в виртуальном дисплее Xvfb:
  ```bash
  xvfb-run -a node wordstat-api.js <список.tsv> --renew --headless
  # или: WORDSTAT_HEADLESS=1 node wordstat-api.js <список.tsv> --renew
  ```
  При `--headless`/`WORDSTAT_HEADLESS=1` браузер не показывается. Для первичного ввода SMS-кода используйте видимый режим один раз (или уже готовую сессию); дальше все сборы — полностью в фоне.
- Выход: `frequencies.tsv` (сводка `id<TAB>запрос<TAB>заголовок<TAB>частота`) и **один сводный документ** `csv/wordstat_<месяц|неделя|день>.csv` со всеми запросами: первый столбец «Период», далее по колонке на каждый запрос (UTF-8 BOM, разделитель «,»). Отдельных файлов по каждому запросу больше нет. При запуске из плагина папка результатов (`outDir`) — это папка задания; рабочие файлы (`frequencies.tsv` и прочие) складывай в подпапку `_raw/`, а итоговый сводный CSV — в `csv/` внутри `outDir`.
- `--summary` — не писать сводный документ, только `frequencies.tsv`. Используется навыком тем (`seo-topics`), которому нужны лишь частотности запросов, а не исторические серии.
- **Ускорение:** флаги `--concurrency N` (параллельные запросы, 1–8) и `--rate R` (запросов в секунду суммарно). Значения по умолчанию (1 и ~0.8/с) полностью совпадают с прежним поведением. Для больших списков разумно `--concurrency 4..6 --rate 3..4`; слишком высокий темп повышает риск капчи/бана сессии. Уже собранные индексы пропускаются (докачка), поэтому сбор можно безопасно возобновлять.

### Как это устроено (для отладки)

- API-база: `https://wordstat.yandex.ru/wordstat/api/<операция>` (POST, JSON, `credentials: include`).
- Операции: `getGraph` (динамика), `getTable`, `getMap`, `getAllTableData`, `getMoreTableData`, `search`.
- Тело `getGraph`:
  ```json
  {
    "currentDevice": "desktop,phone,tablet",
    "currentGraphType": "month",        // month | week | day
    "dbname": "rus",                    // rus | tur
    "filters": [...],                   // регион и пр. (перехватывается из сессии)
    "searchValue": "<запрос>",
    "startDate": "01.09.2024",          // формат ДД.ММ.ГГГГ
    "endDate": "31.08.2026",
    "text": { ... }
  }
  ```
- Ответ: массив точек графика с полями `startTimestamp`, `text`, `absoluteValue` (строка с пробелами), `value`. Для месяца период = месяц года (например «сентябрь 2024»).
- Скрипт перехватывает реальное тело запроса при `--renew` и дальше меняет только `searchValue` (и при необходимости `currentGraphType`/`startDate`/`endDate`) — так формат всегда корректный.

## Запасной способ — через Playwright (обход DOM)

Если API недоступен/протухла сессия, а `--renew` не помогает:

1. Установить проверку: `node -e "console.log(require('playwright').chromium)"` — если ошибка, поставить Playwright (см. выше).
2. Открыть сайт (локализация `ru-RU`).
3. **Авторизация**: при первом запуске открыть браузер в оконном режиме и сохранить профиль в постоянную папку (`./pw-profile`); пользователь сам вводит логин и SMS-код в открытом окне. В следующих запусках переиспользовать тот же профиль через `launchPersistentContext`.
4. Для каждого запроса:
   - Перейти на `https://wordstat.yandex.ru/?region=<id региона>&words=<запрос>` (запрос — URL-encoded).
   - Дождаться загрузки результатов.
   - Кликнуть вкладку `label.radiobox__radio:has-text("Динамика")`.
   - URL станет `...&view=graph`.
   - **Разбивка**: найти переключатель «По месяцам» / «По неделям» / «По дням» (внутренние значения `month` / `week` / `day`) и выбрать нужный. Способ: `page.getByText("По неделям", { exact: true })` и клик; если это `<select>` — выбрать опцию с текстом.
   - **Период**: если задан диапазон, например «с 2024-09 по 2026-11» — выбрать его в селекторе периода. Названия месяцев русские, например «сентябрь 2024».
   - **Регион**: если дан «идентификатор региона в Wordstat: N» — использовать `region=N` в URL. Для «Все регионы» — `region=all`.
   - Из таблицы `<table>` вытащить строки «Период | число запросов» (числа могут быть с пробелами-разделителями тысяч).
   - Если вместо данных страница запросила капчу/вход — снова открыть window-режим с тем же профилем, попросить пользователя пройти проверку.
 5. **Вывод**:
   - Один сводный CSV на задание: `wordstat_<месяцам|неделям|дням>.csv` (периоды в строках, запросы в колонках), UTF-8 с BOM, разделитель «,». В папке результатов — в `csv/`; рабочие файлы — в `_raw/`.
   - В чате — таблица «Период | Число запросов» по каждому запросу.

## Ограничения и правила

- Работать аккуратно, не слать десятки запросов в секунду — Яндекс может показать капчу или забанить сессию.
- Если запросов много — обрабатывать последовательно и писать прогресс (№ / всего).
- Не выкладывать и не использовать чужие данные из аккаунта вне задачи.
- Сессия (cookies) чувствительна: не коммитить `api-session.json` и `pw-profile/` в git.
