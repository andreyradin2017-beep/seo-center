# Технический аудит сайта (методология «Текарт»)

## Результаты пункта 2.3

1. **`Служебные теги.docx`** — отчёт: подводка (зачем нужны title и description), тезисно проблемы,
   тезисно рекомендации, таблица примеров по страницам.
2. Листы в **общей таблице по контенту `Контент_<хост>.xlsx`** (открывать существующий, не создавать новый):
   - **«Текущие метатеги»** — `№, URL, Раздел, Title, Длина title, Description, Длина description, Проблемы`;
   - **«Скорректированные метатеги»** — создаётся, если менять теги нужно глобально (≥ 80 % страниц)
     или если приложено семантическое ядро. Колонки: `№, URL, Раздел, Title (новый), Длина, Description (новый), Длина, Источник`
     (Источник: `семантика` или `правила`).

## Семантическое ядро (важно)

Пункт поддерживает **прикрепление файла семантического ядра** (`.xlsx`/`.csv`) с колонками
`Запросы | Частотность (общая) | Частотность (уточнённая) | Целевая страница`.

- Если семядро приложено → теги составляются **по семантике** (как в навыке `seo-metatags`):
  на каждую страницу — свой кластер запросов, ТОП по частотности идёт в title, остальные — в description.
- Если семядро **не приложено** → базово корректные теги составляются **по правилам**
  (из H1/темы страницы, раздела и текста), и в отчёте указывается, что при наличии семантики теги
  стоит пересобрать повторно.

Путь к семядру передаётся в промте (плагин сохраняет загруженный файл и указывает путь).

## Порядок работы

> **Отчёты о ходе (для прогресс-бара).** Выведи `[[stage:1/3]]` в начале, `[[stage:2/3]]` перед
> анализом тегов и `[[stage:3/3]]` перед сохранением файлов.

1. **Собрать все URL** — как в пунктах 2.1/2.2 (sitemap.xml + краулинг по перелинковке; можно
   переиспользовать подход навыка `seo-metatags-extract`).
2. **На каждой странице** извлечь `title`, `description` (или `og:description`), `H1` и основной текст.
3. **Проверить теги:**
   - **Наличие** — нет title / нет description.
   - **Дубли** — одинаковый title/description на разных страницах (в т.ч. шаблонные).
   - **Длина** — title 50–70 символов; description 150–170 (до 200).
   - **Качество** — description по сути страницы и с точкой на конце; title с ключевым запросом;
     отсутствие «неинформативных» шаблонов (например, «Компания», «Главная страница»).
4. **Составить скорректированные теги** — по семядру либо по правилам (см. выше).
5. **Сформировать** `.docx` и листы XLSX.

## Структура .docx
- Обложка (название 24pt #333333, дата 9pt #942972, таблица проекта).
- `Heading 1` — «Анализ страничных факторов», `Heading 2` — «2.3. Служебные теги».
- **Подводка** — зачем нужны title и description.
- **«В ходе проверки выявлены следующие проблемы:»** — тезисно (наличие, дубли, длина, шаблонность).
- **«Рекомендация:»** — тезисно (правила title/description, уникальность, работа по семядру).
- Примечание про источник тегов (семантика/правила).
- Таблица «Примеры страниц с проблемами служебных тегов» (Страница / Текущий title / Проблема / Скорректированный title).

## Техника

Готовый скрипт: `scripts/meta_audit.py`. Запуск:

```bash
python3 scripts/meta_audit.py --url https://<host>/ --out-dir <папка> [--semcore <файл.xlsx|.csv>] [--brand <Бренд>]
```

Скрипт сам: собирает URL, извлекает теги, находит проблемы, составляет скорректированные title/description
(по семядру или по правилам), пишет листы «Текущие метатеги» и «Скорректированные метатеги» в
`Контент_<хост>.xlsx` и сохраняет `Служебные теги.docx`.
Зависимости: `pip3 install --break-system-packages requests beautifulsoup4 openpyxl python-docx`.

## Что НЕ относится к пункту 2.3
- Текст (уникальность, вода, переспам, объём) — 2.1.
- Структура заголовков H1–H6 в тексте — 2.2.
- Изображения — 2.4; исходящие ссылки — 2.5; микроразметка — 2.6.
- Адресация/дубликаты/индексация/перелинковка — пункты 1.1–1.5.

## ОБЯЗАТЕЛЬНЫЕ ПРАВКИ ДМИТРИЯ (обязательно)
- Title — 50–100 символов. Description — 170–250 символов. Соблюдать при генерации.
- Не обрезать title/description посреди слова ради лимита; писать нормально, без фанатизма.
- Примеры в таблицах проверять: исправленный вариант не должен быть обрывком или равным проблемному.
- Про метатеги писать «скорректировать, см. пункт N» и ссылаться на пункт выше в аудите.
- Если семантическое ядро приложено — писать «метатеги составлены с учётом запросов из сем. ядра»; фразу про «не приложено» НЕ писать.
- Не писать слово «хост» — сразу название файла таблицы и вкладку.
- Учитывать информационные страницы (напр. /useful/encyclopedia/).
- Положительное — отдельным блоком; к рекомендации — 1 буквальный пример.
