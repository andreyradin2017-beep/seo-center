# Технический аудит сайта (методология «Текарт»)

Проводим технический SEO аудит сайта и оформляем результаты в `.docx` по заданному шаблону.

## Формат итогового документа

- Обложка: название аудита (24pt, #333333), дата (9pt, #942972), таблица данных проекта (Заказчик / Документ). Без брендинга «Текарт» — без копирайта, дисклеймера и контактов менеджера.
- «Содержание» — список разделов.
- Заголовки: Heading 1 / Heading 2 (5.1).
- Подраздел: краткая подводка (зачем это нужно с точки зрения SEO) → выявленные проблемы → блок «Рекомендация:» жирным.
- Где нужно — таблицы, списки URL, код (robots.txt, llms.txt).
- **Указывать, сколько страниц проверено.**

## Шаг 0. Единый сбор данных (общий коллектор)

Запусти общий краулер-коллектор — один обход собирает robots.txt, sitemap и данные страниц (title, canonical, og, jsonld/microdata, URL):

```bash
python3 .opencode/tools/seo_collect/site_collect.py --url <URL сайта>
```

Скрипт печатает путь к JSON (строка `OUT=...`, по умолчанию `/tmp/opencode/seo_collect/<хост>.json`) и кэширует его на 2 часа. Файл `llms.txt` проверяй напрямую (`https://<host>/llms.txt`). Дальше данные бери из JSON/файлов — сайт повторно вручную НЕ обходи.

Что в JSON:
- `robots` (`status`, `text`) — содержимое robots.txt;
- `sitemap` (`found`, `urls`, `files`);
- `pages[]` — по каждой странице: `url`, `status`, `canonical`, `lang`, `headings`, `og`, `jsonld_types`, `microdata_types`, `links_internal`, `soft404`.

Ключи: `--refresh` — пересобрать кэш; `--limit N` — ограничить число страниц; `--no-link-check` — быстрее.

## Порядок работы по пункту 5.1 «GEO/AEO аудит»

> **Отчёты о ходе (для прогресс-бара).** При запуске из плагина выведи `[[stage:1/3]]` в начале, `[[stage:2/3]]` перед анализом и `[[stage:3/3]]` перед формированием `.docx`.

1. Читаем JSON коллектора и напрямую проверяем служебные файлы:
   - `https://<host>/robots.txt`;
   - `https://<host>/llms.txt`.
   Проверять варианты `http`/`https` и `www`/без-www.
2. Для каждой части — **краткая подводка**, зачем это нужно с точки зрения GEO/AEO.
3. Анализируем:
   - **robots.txt** — доступность ИИ-краулеров (GPTBot, Google-Extended, ClaudeBot, PerplexityBot, anthropic-ai, cohere-ai, AI2 и др.). Если для ИИ-бота стоит `Disallow: /` — ошибка, нужно открыть. Проверять секции `User-agent:`.
   - **llms.txt** — наличие файла в корне, корректность: заголовок `# <Компания>`, разделы `##`, список ключевых URL с анкорами, язык (для русскоязычного сайта — русский), отсутствие битых ссылок.
   - **Структурированные данные** — JSON-LD/Microdata: `Article`, `NewsArticle`, `BlogPosting`, `Organization`, `LocalBusiness`, `BreadcrumbList`, `FAQPage`, `Product`. ИИ-поисковики считывают разметку, чтобы цитировать сайт.
   - **OpenGraph** — `og:title`, `og:description`, `og:image`, `og:url`, `og:type`.
   - **https / canonical / читаемые URL** — работа по https, наличие `rel=canonical`, отсутствие кириллицы в пути, лишних параметров и двойных слешей.
4. Формируем **рекомендации** по каждой проблеме: как исправить, с примерами.

## Техника

Использовать `requests` (при необходимости `pip3 install --break-system-packages requests`).
- robots.txt парсить по секциям `User-agent:`; для каждого ИИ-агента проверять, есть ли `Disallow: /`.
- llms.txt проверять по структуре: заголовок `#`, разделы `##`, ссылки `[анкор](url)`; ссылки проверять на отклик без следования редиректам (любой 4xx/5xx — битая).
- При сомнении — проверять страницы самому; не писать «регулярно перепроверять…» и не описывать то, что не является проблемой.

## Техника генерации .docx

Использовать `python-docx` (`pip3 install --break-system-packages python-docx`).
- `doc.styles['Normal'].font.size = Pt(10)`
- Обложка: заголовок Pt(24) 0x333333; дата Pt(9) 0x942972; «Содержание» Pt(20) 0x333333. Без «Текарта».
- Раздел: `add_heading('5.1. GEO/AEO аудит', level=2)`.
- Код (robots.txt, llms.txt) — моноширинный шрифт (`Courier New`), каждая строка с новой строки.
- «Рекомендация:» — `run.bold = True`; перечисления — `List Bullet`.
- «Положительное» — отдельным блоком, до списка недостатков.

## Если проблем нет

Даже если по пункту проблем не выявлено — всё равно дай краткую подводку (зачем этот пункт нужен), а в блоке проблем напиши: «Проблем на сайте не обнаружено, исправления не требуются.»
