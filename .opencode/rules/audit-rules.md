# Правила SEO-аудита (обязательны в каждом прогоне)

Источник — 46 комментариев Дмитрия к аудиту pokras.ru. Агент читает этот файл
перед сборкой отчёта и выполняет буквально. Панель читает `audit.json` из той же
папки, поэтому его схема — часть контракта.

## Структура единого документа

- Сохраняй названия пунктов и блоков: «Анализ дружественности сайта поисковым
  машинам», «Анализ страничных факторов», «Внешние показатели», «Анализ
  технических факторов со стороны сервера».
- Нумеруй только ВЫБРАННЫЕ пункты сквозной нумерацией без пропусков: блоки по
  порядку 1, 2, 3…, пункты внутри — `<блок>.<номер>`. Пример: выбраны 1.2, 1.4 и
  3.1 → «1.1. Дубликаты страниц», «1.2. Индексация сайта», «2.1. Сниппеты».
- Неотмеченные пункты в документ не включай.
- Титульный лист: только название аудита, домен и дата. Без таблицы
  «Заказчик/Документ/Дата».
- Если по пункту проблем нет — краткая подводка (зачем пункт) и строка
  «Проблем на сайте не обнаружено, исправления не требуются.»
- Отчёты о ходе: `[[stage:1/3]]` в начале, `[[stage:2/3]]` перед сборкой,
  `[[stage:3/3]]` перед сохранением .docx.

## Подача

- В каждом пункте указывай, СКОЛЬКО страниц проверено.
- «Положительное» — отдельным блоком ДО списка недостатков.
- К каждой рекомендации — ровно 1 буквальный пример «как должно быть».
- Не описывай очевидности и то, что не является проблемой; без воды.
- Не пиши «регулярно перепроверять…».
- Где можно — оформи исправленный файл (docx/txt) и сошлись на него: «внедрите».
- Не обрывай фразы и заголовки посреди слова; ссылки — полными URL.
- Термины: «недоступны» (не «недостижимы»), «lazy load» (не «ленивая загрузка»).
- Не пиши про аналитику/счётчики, «ссылочные облака», `target="_blank"` без
  `noopener`, `rel="sponsored"` и термин «dofollow».
- Не пиши слово «хост» — называй файл таблицы и вкладку.

## Meta / H1 / контент

- Title — 50–100 символов, description — 170–250. Не обрезать посреди слова.
- Примеры в таблицах проверяй, чтобы не было обрывков.
- Про метатеги: «скорректировать, см. пункт N» со ссылкой на пункт выше.
- Совпадение текста пиши приблизительно («на 90%»).
- Если семядро приложено — «метатеги составлены с учётом запросов из сем. ядра»;
  фразу «не приложено» не пиши.
- Инфо-страницы учитывай в расчёте среднего объёма.

## Canonical, robots, sitemap, разметка

- Canonical: НИКОГДА «поставить на все страницы сам на себя». Только точечно и
  на примерах (пагинация, каталог с цветами). Нет полезного вывода — не пиши.
- Robots: не утверждай, что список закрытых адресов устарел — перепроверяй
  страницы. Не пиши про правила для ИИ-ботов. Директива `Disallow: /*?` должна
  быть во всех robots: нет — ошибка, есть — ок. Если пишешь «не рекомендуется» —
  указывай причину.
- Sitemap: не рекомендуй `rel=next/prev` (устарело), не поясняй очевидное
  (changefreq/priority).
- Микроразметка: только типы из справочника Schema.org. JSON-LD — для Article,
  NewsArticle, BlogPosting, Movie, Review, Recipe, QAPage; остальное — Microdata.
  Без WebSite/SearchAction, ItemList/CollectionPage и Twitter-тегов.
- Даты — ISO 8601 (`2025-03-15` / `2025-03-15T10:30:00+03:00`), длительность —
  `PT1H30M`.
- Для контента Яндекс требует `@id`, `headline`, `text (articleBody)`, минимум
  500 символов.
- Перебои в работе — проверяй через https://ping-admin.ru/free_test/ и давай
  корректную ссылку; не пиши, кто что вернул.
- Сниппеты: если капчу не обойти и нормальных скриншотов нет — пункт не делай и
  напиши, что не вышло.

## GEO/AEO аудит (пункт 5.1)

- Проверять, что сайт доступен для ИИ-краулеров (GPTBot, Google-Extended, ClaudeBot,
  PerplexityBot и др.) в robots.txt. Если заблокированы — ошибка, нужно открыть.
- Наличие файла `llms.txt` на корне сайта с кратким описанием компании, ссылками на
  ключевые страницы и контактной информацией.
- Наличие структурированных данных JSON-LD/Microdata (Article, Organization,
  BreadcrumbList, FAQPage, Product и др.) на страницах.
- Наличие OpenGraph тегов (og:title, og:description, og:image, og:url, og:type).
- Наличие корректного `rel=canonical` на страницах.
- Сайт должен работать по HTTPS.
- URL должны быть читаемыми (латиница, без лишних параметров, без дублей со слэшем/без слэша).

## Общие выводы (в конце документа)

- Heading 1 «Общие выводы»: 1–2 вводных предложения (сколько проблем и что они
  затрагивают).
- Тезисный список по КАЖДОМУ исследованному пункту: что не так → что исправить →
  «(подробнее в п. X.Y)» → «Критичность: Высокая/Средняя/Низкая».
- Ориентир: Высокая — индексация/доступность/видимость; Средняя —
  ранжирование/качество; Низкая — косметика.
- Сводная «Таблица. Рекомендации»: «Пункт», «Что исправить», «Критичность» — по
  строке на каждый исследованный пункт.
- Таблицы XLSX рядом с .docx: пункты 2.1–2.5 и 3.2 → `Контент_<хост>.xlsx`;
  4.1 → `Скорость_<хост>.xlsx`. Пустые не создавай.

## Язык

Живой деловой, без «ИИ-штампов»: без пустых зачинов («в современном мире»,
«стоит отметить», «важно понимать»), канцелярита («осуществляется», «в рамках
данного», «с целью»), промо-эпитетов («широкий ассортимент», «высокое качество»).
Вместо оценок — конкретика, цифры, факты. Слово «уникальный» в SEO-контексте
допустимо. Не злоупотребляй тире и не делай «синонимическую карусель».

После сохранения «SEO-аудит.docx» выполни
`python3 .opencode/tools/slop/scripts/slop_check.py "<путь к SEO-аудит.docx>"`.
Есть срабатывания high (кроме дефисных терминов) или много medium — исправь и
перезапиши. Смешение кириллицы и латиницы (например «Cостояние») исправляй
только в НАШЕМ тексте; в цитатах страниц сайта и данных таблиц не меняй.

## audit.json (контракт с панелью)

Рядом с .docx сохрани `audit.json` — всегда, даже если проблем нет. Панель
считает по нему скор, историю, дельту, статусы проблем и уведомления.

```json
{
  "host": "example.com",
  "site": "https://example.com/",
  "generatedAt": "2026-11-12T10:30:00+03:00",
  "summary": "Короткий итог прогона",
  "points": [
    {
      "point": "2.3",
      "title": "Служебные теги",
      "checkedPages": 40,
      "summary": "Что проверено и общий вывод",
      "positive": ["Что уже хорошо"],
      "issues": [
        {
          "title": "Пустые title",
          "severity": "high",
          "urls": ["https://example.com/page"],
          "fix": "Конкретная правка",
          "count": 12
        }
      ]
    }
  ]
}
```

- `severity` — только `high`, `medium`, `low`.
- `point` — номер пункта как в задании; `title` — название пункта.
- `urls` — полные URL затронутых страниц (можно до 200).
- Пункт без проблем: `"issues": []`.
- `checkedPages` — сколько страниц реально проверено по пункту.
