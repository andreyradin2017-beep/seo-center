# Что изменилось в проекте относительно исходной версии

Для владельца: коротко и по-человечески — что мы добавили, что поправили и что
намеренно не трогали. Код и архитектура при этом не «переделывались наново»,
всё сделано точечно и минимально.

## 1. Что добавили как новые функции

**Аналитика аудитов.** Раньше панель умела запускать навыки и показывать файлы —
и всё. Теперь по каждому прогону аудита панель считает:
- **скор 0–100** и гейт («пройден / замечания / не пройден»);
- **историю прогонов** по каждому сайту;
- **дельту между аудитами** — что добавилось, что исправилось, как изменился скор;
- **список проблем** с URL (по которым можно вести работу: открыта / в работе /
  исправлена / игнор);
- **расписание** — авто-повтор аудита сайта (каждые N дней в заданный час);
- **Telegram-уведомления** о завершении аудита.

Всё это — новая страница **«Аналитика»** (в шапке панели), доступна только
администраторам.

Для этого ввели файл-контракт **`audit.json`**: агент после аудита кладёт его
рядом с отчётом, а панель по нему считает все показатели. Этого не было — раньше
результаты были только «в docx».

**Генераторы файлов.** Новая страница **«Генераторы»**: готовые `robots.txt`
(с обязательным закрытием параметров `Disallow: /*?`), `sitemap.xml` (в т.ч. из
CSV с перечнем URL), и **JSON-LD** с проверкой корректности (даты, обязательные
поля) — по справочнику микроразметки.

**Удобство запуска аудита:**
- **пресеты пунктов** — сохранил набор пунктов, применяй одним кликом;
- кнопка **«Повторить»** у любого прогона в истории;
- все пути запуска (форма, повтор, планировщик) используют один и тот же код,
  поэтому результаты не расходятся.

**Внешние сервисы** (проверяются на вкладке «Интеграции»): PageSpeed Insights,
Google Search Console, Яндекс.Вебмастер, Яндекс.Метрика. Без OAuth-флоу: вставляешь
готовый ключ/токен, жмёшь «Проверить» — показывает, работает ли.

**Общий HTTP-кэш для скриптов аудита** — чтоб на каждом пункте не качать сайт
заново (6 Python-скриптов принимают `--cache`).

## 2. Что поправили по ходу

- Показ ошибки проверки интеграций без ключа (отображалась не та строка) — теперь
  показывается причина.
- Скрипт 2.3 «Служебные теги» писал фразу «семантическое ядро не приложено» —
  она противоречит вашим же правилам; заменили на нейтральную формулировку.
- Тест на POSIX-права файлов (chmod 600) не проходил на Windows — для Windows
  проверка пропускается (это особенность ОС, а не кода).
- Пустой тестовый скрипт `npm test` в `package.json` заменили на настоящий
  запуск тестов.
- README: убрали упоминания файлов, которых нет в этом архиве (`geo-aeo-tracker`,
  отдельный `seo-panel/panel.ts` — они есть только на боевом сервере).
- Правила аудита вынесены в один файл `.opencode/rules/audit-rules.md` — промпты
  ссылаются на него как на единый источник.

## 3. Что проверено

- **33 теста** (юнит + e2e панели через настоящий HTTP-сервер) — проходят.
- **Живой прогон на реальном сайте qegg.ru** (436 страниц, пункт 2.3):
  скор 68/100, найдено 4 проблемы (дубли title/description, длинные
  title/description) — вся цепочка «скрипт → audit.json → аналитика в панели»
  работает на настоящих данных, ошибок в консоли браузера нет.

## 4. Что намеренно не трогали

- **Авторизацию** — по вашему решению оставили как есть.
- Пункты плана, которые вы отклонили: «трафик/важность URL и топ-10 правок» и
  «HTML/PDF-отчёт с брендом + публичная ссылка».
- Пороги длины title/description в скриптах (30–70 / 70–200) — по вашему решению
  оставили как есть (в правилах проекта при этом 50–100 / 170–250; если захотите —
  приведём пороги скриптов к правилам).
- `geo-aeo-tracker` и развязанный `seo-panel/panel.ts` — их нет в этом архиве,
  они остаются только на боевом сервере.
