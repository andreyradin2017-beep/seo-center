# Что изменилось в проекте относительно исходной версии

Для владельца: коротко и по-человечески — что мы добавили, что поправили и что
намеренно не трогали. Код не «переделывали наново», всё сделано точечно и
минимально. После этих изменений все 37 тестов проходят (`node --test .opencode/tests/`),
включая e2e-панель на настоящем HTTP-сервере.

## 1. Новые функции

**Аналитика аудитов.** Раньше панель умела запускать навыки и показывать файлы —
и всё. Теперь по каждому прогону аудита панель считает:
- скор 0–100 и гейт (пройден / замечания / не пройден);
- историю прогонов по каждому сайту;
- дельту между аудитами (что добавилось / исправилось / как изменился скор);
- список проблем с URL и статусами (открыта / в работе / исправлена / игнор);
- расписание — авто-повтор аудита сайта (каждые N дней в заданный час);
- Telegram-уведомления о завершении аудита.

Новая страница **«Аналитика»** (`/insights`, только admin/it). Ввели файл-контракт
**`audit.json`**: агент кладёт его рядом с отчётом, панель по нему считает все
показатели.

**Генераторы файлов.** Новая страница **«Генераторы»** (`/generators`, только
admin/it): `robots.txt` (с обязательным `Disallow: /*?`), `sitemap.xml` (в т.ч.
из CSV со списком URL) и **JSON-LD** с проверкой корректности (даты,
обязательные поля) по справочнику микроразметки.

**Удобство запуска аудита:**
- пресеты пунктов — сохранил набор пунктов, применяем одним кликом;
- кнопка **«Повторить»** у любого прогона в истории;
- все пути запуска (форма, повтор, планировщик) используют один и тот же код
  (`enqueueAudit` / `buildAuditPrompts`) — результаты не расходятся.

**Внешние сервисы** (вкладка «Интеграции»): PageSpeed Insights, Google Search
Console, Яндекс.Вебмастер, Яндекс.Метрика. Без OAuth-флоу: вставляете готовый
ключ/токен, жмёте «Проверить».

**Общий HTTP-кэш для скриптов аудита** — на каждом пункте сайт не качается
заново (6 Python-скриптов принимают `--cache`).

## 2. Правки в коде

**Параметры аудита не теряются при повторе и в планировщике** (пункт 1 из плана):
- `RunRecord` и `Schedule` получили поля `depthContent`, `depthSpeed`,
  `semcoreMsg`, `semcorePath`.
- «Повторить» берёт глубины 2.1/4.1 и семядро из последнего прогона сайта.
- Планировщик берёт глубины из расписания, а если не заданы — из последнего
  прогона сайта.
- При создании расписания можно указать глубины через API/UI.

**Ложные дубли title/description убраны через каноник** (пункт 2 из плана, высокая
критичность):
- Скрипт 2.3 (`meta_audit.py`) нормализует URL (убирает trailing slash,
  `?PAGEN_1=2` и т.п.) для группировки дублей.
- Извлекает `rel=canonical` со страницы. Страница не считается проблемным дублем,
  если на неё стоит canonical на другую страницу группы (пагинация, слэши,
  фильтры). Реальные дубли остаются, ложные — убираются из скора.
- Пороги длины приведены к правилам проекта: **title 50–100, description 170–250**
  (было 30–70 / 70–200). Правила зафиксированы в `.opencode/rules/audit-rules.md`
  и дублируются машинночитаемым `.opencode/rules/audit-rules.json`, который читают
  скрипты — единый источник правил для агентов и кода.

**Машины состояний (UX/DX/AX)** (пункт 6 из плана):
- `setIssueStatus` валидирует допустимые переходы статусов проблемы
  (open→in_progress→fixed/ignored, регресс fixed→open, и т.п.); недопустимые
  переходы отклоняются.
- `/api/audit-queue` отдаёт `stateLabel` (выполняется / в очереди) для удобства
  UI и агентов.
- `finishAuditJob` помечает задачу `done` перед удалением.
- Расписание в UI показывает «Следующий запуск» (вычисляется из everyDays,
  hour, lastRunAt).
- Расписание хранит `depthContent/depthSpeed`.
